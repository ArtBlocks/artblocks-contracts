Add `MinterSetPricePMPV0`, a shared minter-suite set price ETH minter that can configure a project's post-mint params (PMPs) in the same transaction as the mint. Alongside the standard `purchase` and `purchaseTo`, it adds `purchaseWithPMPs` and `purchaseToWithPMPs`, which accept an array of PMP inputs and forward them to the PMP contract set immutably at deploy time. Any number of params may be configured in a single purchase, and the PMP-accepting functions require at least one input. Because PMP authenticates the caller of `configureTokenParams` — this minter, not the purchaser — the project's artist must configure each key that should be settable at mint time with an `authOption` that includes `Address` and an `authAddress` of this minter; `TokenOwnerAndAddress` also lets the collector update the value after the mint. Purchases that pass a key which is not part of the project's active PMP config, or which does not authenticate this minter, revert.

The artist may also mark a set of PMP keys as required at mint via `setProjectRequiredPMPKeys`, which accepts up to 256 unique keys. Each key is validated at configuration time to be part of the project's active PMP config, to authenticate this minter via an address-based `authOption`, and to never lock. While a project has required keys, only `purchaseWithPMPs` and `purchaseToWithPMPs` may be used, and every required key must be present in the submitted inputs; extra non-required keys are still permitted, in any order. The keys are readable on chain via `projectRequiredPMPKeys`.
